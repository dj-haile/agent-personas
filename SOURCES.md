# SOURCES — provenance map for citation shorthands

This project (agent-personas) is **functionally standalone**: every persona spec restates the numbers and mechanisms it depends on inline, and nothing here needs an external file to *operate* (the one prior exception, `eval-review-agent.md`, is now vendored at `reference/eval-review-agent.md`).

What is *not* inside this project is the research corpus the catalog cites for provenance. Every claim in `org-agent-personas-catalog.md` and `coverage-and-gap-audit.md` was verified against those sources (July 2026 audit); this file maps the citation shorthands to their origin documents so the trail survives if this folder is extracted from its parent repo.

**Corpus location:** the private companion repo `article-research-automation` (this project originated inside it and now stands alone). Citations remain readable as provenance; checking them requires access to that corpus.

| "Source 119" (Morrell object-capability / capability references — cited by `decisions/chief-of-staff-code-mode-handoff.md` and `conventions/code-mode-for-reads.md`) | Jeremy Morrell (Cloudflare), ["Extensible Software in the Age of LLMs"](https://jeremymorrell.dev/blog/extensible-software-in-the-age-of-llms/), published 2026-08-18. Corpus: `scout-reports/proposed/applied/2026-08-19-use-morrell-capability-extension.md` (staged as proposed source 98; applied 2026-08-19 as Source 119 to playbook row 135, architecture handoff, constellation `added:"2026-08-19"`). Claim: LLM-authored extension code should receive narrow typed functions (object-capability, e.g. `getApprovedEmail()`), not a scoped API key behind a filtering proxy — the proxy degrades into per-endpoint filtering that must track every backing-API change and still exposes the credential, while a typed TypeScript signature is smaller and more familiar to the model than an OpenAPI JSON schema. Ambient I/O is removed; the code can act only via references it was handed. Production evidence cited: Pi (Prime Radiant), opencode2 (68 internal plugins), deepseek harness, Cloudflare Dynamic Workers; Salesforce Apex as 20-year precedent. Scope: the extension/plugin case (third-party code); platform-owned tool calls that already hide credentials are unaffected — reviewed and accepted with that clarification. |
| "Source 120" (Code Mode — cited by `decisions/chief-of-staff-code-mode-handoff.md` and `conventions/code-mode-for-reads.md`) | Vercel AI SDK docs, ["Code Mode"](https://ai-sdk.dev/docs/ai-sdk-core/code-mode) (`mode: "code"` on `generateText`), Aug 2026; underlying pattern Varda & Pai (Cloudflare), "Code Mode: the better way to use MCP," Sept 2025. Corpus: `scout-reports/proposed/applied/2026-08-19-use-ai-sdk-code-mode.md` (staged as proposed source 99; applied 2026-08-19 as Source 120 to playbook row 136, architecture handoff Patterns 7 and 9, constellation). Claim: models are more accurate on multi-step tool workflows (3+ chained calls with dependencies — transform, filter, join, retry) when they write JavaScript/TypeScript against a typed capability API executed in a V8 isolate (millisecond cold start, single-digit MB, no ambient network) than when emitting structured tool calls one at a time — the code-writing training prior is vastly larger than the tool-call-schema prior. Explicit non-fit: single-tool-call workflows (sandbox cost isn't free); not a substitute for credential enforcement at the tool-implementation layer. Security caveat: the sandbox becomes the security perimeter — Check Point, "When Agentic Glue Melts" (2026), documents the misconfiguration attack surface (ambient fetch, host FS mounts, shared isolates). Composes with Source 119: the capability reference is the shape; Code Mode is the authoring surface. |
